## 2. 題目說明
模擬遊戲「踩地雷」的提示數字生成過程
- **輸入:** 
  1. 每組測資開頭為兩個整數 n (列數) 與 m (行數)，最大不超過 100
  2. 接著有 n 列字串，每列包含 m 個字元，* 代表地雷，. 代表安全的空地
  3. 當 n = 0 且 m = 0 時，結束程式
- **預期輸出:** 將原本的 . 替換成空地周圍 8 個方向的地雷總數，地雷本身保持不變，每組測資需加上 Field #x: 的標頭
- **主要規則或限制**
  1. 必須考慮周圍 8 個方向
- **核心任務:** 找出所有空地相鄰的地雷數量，並正確輸出修改後的矩陣

## 3. 思考邏輯與解題策略

### 初始想法

- 宣告一個大小剛好為 n * m 的二維陣列，用雙層迴圈遍歷每一個格子，如果是空地，就檢查它周圍的 8 個格子
- 當格子在邊界（例如 i = 0 或是 j = 0）時，去檢查 i - 1 或 j - 1 會導致陣列索引變成負數，進而引發記憶體越界錯誤，如果每個方向都要寫 if (i > 0 && j > 0) 等條件判斷，程式碼會變得非常冗長且容易出錯

### 最終策略

- 宣告一個比題目要求稍大一點的陣列並初始化為空字元 0，讀取地圖時，從索引 1 開始存入，到 n 與 m 結束，這樣外圍自然形成了一圈用0圍住的防護網，避開越界問題
- 讀取輸入時，直接把空地 . 轉換為字元 '0'。在計算周圍地雷時，只要發現一顆地雷，就直接對該格子的字元執行遞增操作 (field[i][j]++)。因為 '0' 的 ASCII 碼加 1 就會變成 '1'，省去了整數與字元之間轉換的麻煩

## 4. 虛擬碼

```text
START
1. 初始化測資計數器 cnt = 1
2. 只要 讀取到 n 與 m 且兩者不皆為 0：
   a. 宣告並初始化大小為 110x110 的字元陣列 field，預設為空字元
   b. 讀取地圖資訊 (從索引 i=1 到 n，j=1 到 m)：
      - 如果讀入的字元是 '.'，將其轉為字元 '0'
   c. 遍歷地圖中的每個格子 (從索引 i=1 到 n，j=1 到 m)：
      - 如果當前格子不是地雷 '*'：
        - 檢查周圍 8 個方向，若該方向字元為 '*'，則將當前格子字元 +1 (field[i][j]++)
   d. 輸出 "Field #cnt:"
   e. 輸出更新後的地圖陣列
   f. 輸出換行，並將 cnt + 1
END
```

### 正確程式碼

```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
	int n, m;
	int cnt = 1;
	while(cin >> n >> m && n != 0 || m != 0){
		
		char field[110][110] = {0};
		
		for(int i=1; i<=n; ++i){
			for(int j=1; j<=m; ++j){
				cin >> field[i][j];
				if(field[i][j] == '.') field[i][j] = '0';
			}
		}
		
		for(int i=1; i<=n; ++i){
			for(int j=1; j<=m; ++j){
				if(field[i][j] != '*'){
					if(field[i-1][j-1] == '*') field[i][j] ++;
					if(field[i][j-1] == '*') field[i][j] ++;
					if(field[i+1][j-1] == '*') field[i][j] ++;
					if(field[i-1][j] == '*') field[i][j] ++;
					if(field[i+1][j] == '*') field[i][j] ++;
					if(field[i-1][j+1] == '*') field[i][j] ++;
					if(field[i][j+1] == '*') field[i][j] ++;
					if(field[i+1][j+1] == '*') field[i][j] ++;
				}	
			}
		}
		
		cout << "Field #" << cnt << ":\n";
		cnt ++;
		for(int i=1; i<=n; ++i){
			for(int j=1; j<=m; ++j){
				cout << field[i][j];
			}
			cout << "\n";
		}
		cout << "\n";
	}
}
```

## 6. 差異與反思

### 關鍵差異

| Item | Fail Code | Correct Code |
|---|---|---|
| 邏輯 |  | 直接存取 8 個方向，藉由外圍的空字元防護圈吸收越界存取 |
| 邊際情況 |  | 從索引 1 開始存取，邊界檢查自然相容，邏輯極度簡潔 |
| 輸出處理 |  | 直接利用 ASCII 碼特性 ++，原地修改並輸出 |

### 反思
- 「資料預處理」比「複雜的邏輯判斷」更好用，寫一堆 if-else 來防堵越界，不如把陣列開大一點，從索引 1 開始放資料，這種 1-based indexing 搭配 Padding 的技巧在處理棋盤、網格類的題目時非常實用
- UVa 通常要求的是「兩組測資之間」要有一個空白行，而不是「每一組測資之後」都有空白行，如果未來遇到類似題目一直得到 PE，可以改用條件判斷 if (cnt > 1) cout << "\n"; 放在讀取新測資後的開頭來解決
